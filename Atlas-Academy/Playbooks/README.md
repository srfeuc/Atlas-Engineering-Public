# Atlas Academy — Playbooks

<!-- provenance -->
> **Book 9 — Atlas Academy · the action layer (`ADR-0053`).** The other layers answer *what to test* (cert-maps), *why it works* (`../Concepts/`), and *how to check it* (`../Command-Library/`). **Playbooks answer *"it's broken / I need to operate it — what do I do?"*** Each Playbook is a **scenario named for the problem** — so it's found by search, and each maps 1:1 to a ticket title (the briefcase principle, `Academy-Vision-and-Scope.md`).

> **Find it by the name of your problem.** The filename *is* the problem ("port already in use", "trace a blocked flow"). This is a ≤3-click hop from the repo front door: `README → Academy → Playbooks → the playbook` (`ADR-0053` §4).

> **Runbooks (the "how do I do / automate a technique" set — JSON · Python · PowerShell · IaC · Linux CLI) are a separate layer that arrives with the automation work** (`ADR-0048` / Backlog #19). This folder is troubleshooting + operations only.

> **Checklists cross-link both ways (`ADR-0053` §8).** A commissioning checklist links *down* to the Playbook for a step that fails; a Playbook links *back* to the checklist phase — "check the commissioning checklist for this item." Loop: `00-Atlas-Foundation/Templates/New-Windows-Server-Commissioning-Checklist-TEMPLATE.xlsx` (the golden master) ↔ `Domain-Join-Fails.md` (its Phase-5 fix).

## Writing a new Playbook

Copy the template shape from the 🥇 **golden-template reference [`Read-the-Cert-Not-the-Sign-Log.md`](Read-the-Cert-Not-the-Sign-Log.md)** (or `ADR-0053` §5): frontmatter + provenance · **the one-line problem** · **Symptoms & search terms** 🆕 · **On this page** index 🆕 · **cert anchor** · **grounded in** · **① Pin it down** · **the diagnosis path** (each step: check → command → healthy vs broken → where it points, with **per-step provenance** to the `CM-####`/`MC-####` that proved it) 🆕 · **the fix** (+ prove it) · **if still broken** · **Gap / what this closes** *(optional)* · **Worked example → the CM doc** 🆕 · **Related** · **Worked log** · Change Log. Rules: **filename = the problem name**; **link down** to `../Command-Library/` for the actual commands (don't restate them, `POL-0008`); **never invent output** (`POL-0001`) — 🟡 until a real read-back is pasted; anchor every step to a **real Atlas device**.

> 🔎 **Make it findable — Backlog `#32` (required, `ADR-0053` §5).** Every Playbook carries a rich, plain-spoken **Symptoms & search terms** block so the offline briefcase surfaces it when the operator types *what he is seeing, in his own words*: **verbatim error strings** (quoted, so a pasted error lands here) · **plain-language symptom phrases** ("looks connected but I can't reach it") · **aliases / also-known-as** (synonyms + the tool/protocol/device names) · a **keywords line** (device names, commands, ports, cert names, the `CM-####` anchor). Filename = the problem in plain words = the ticket title. Anchor the page to `#32` in its Status/Related. Keep it honest (`POL-0001`) — symptoms/aliases are fine; command *output* stays 🟡 until a real read-back is pasted.
