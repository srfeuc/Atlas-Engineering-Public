# POL-0003 — Change Control

> **At a glance.** A change that crosses a silo boundary requires a Change Record. A correction is verified by **counting the OLD text to zero** and must reach the document that *does* the work — not just the one that describes it. A record does not close until its evidence is read back. This policy folds the estate's change discipline into citable requirements (`POL-0003 R1`…) and doubles as a directory of the decisions that govern change (below).

## Scope & applicability

Governs every change to a device, service, or document that **crosses a silo boundary** ([`ADR-0018`](../Decisions/ADR-0018-Atlas-Operating-Model-Silos.md)) — and how corrections are verified and closed.

**Boundary with [`POL-0006`](./POL-0006-Evidence-and-Verification.md):** POL-0006 owns the *read-back rule itself* (what counts as evidence); POL-0003 owns the *change process* that requires a read-back to close. A change within one silo, inside an accepted design, needs no record; a boundary crossing always does.

## Why this is a policy, not a note

Every disaster in Book 1 was a boundary crossing nobody paused at (`CM-0011` degraded a BMC; `CM-0014` shipped a secret; RADIUS-on-MKT01 was never finished), and **twelve records were closed with corrections *appended* while the error was left in place** — including the two highest-severity ones. Change discipline that lives only in habit isn't enforceable; as a policy it's auditable.

## The standing requirements

Each is citable as `POL-0003 R#`.

### R1 — A boundary crossing gets a Change Record

A change that crosses a silo boundary requires a Change Record ([`ADR-0018`](../Decisions/ADR-0018-Atlas-Operating-Model-Silos.md)); the CR template's **`Silo(s) / boundary crossed`** field records it — a blank there means nobody decided who owns the change.

### R2 — Small, testable, reversible, one at a time

One logical change at a time; don't combine unrelated changes (Charter Rule 7). A change you can't reverse or test in isolation is a change you can't audit.

### R3 — Verify a correction by counting the OLD text to zero

Appending the fix while leaving the error is **not** fixing it (Charter Rule 16 / `016` R1). `git grep` the old string; it must return **0**. A redaction added beside a live value greps non-zero — the `CM-0014` failure mode.

### R4 — Fix the document that DOES the work first

Correct the runbook/build guide that *builds* the thing, not only the one that *describes* it (`016` R2). `035` was read every issuance and never opened; `031` was corrected five times while the doing-doc drifted.

### R5 — Guide reconciliation is required; a record closes only on a read-back

For every guide a change touched, answer **in writing**: *does it now teach a step that recreates this problem?* (Charter Rule 15). And a record **closes only when its read-back evidence exists** — if a closeout box can't be truthfully ticked, the status is `Implemented — reconciliation open`, not `Closed` ([`POL-0006`](./POL-0006-Evidence-and-Verification.md)).

## The amendment model — how these decisions relate to this policy

This policy holds the **current** rule; the decisions behind it are the **dated trail**. To change a rule, an ADR carries `Governing Policy: POL-0003`, states *"amends `POL-0003` R#"*, and a Change Log row is added ([`ADR-0054`](../Decisions/ADR-0054-Governance-Reconciliation-Promote-Policy-Shaped-ADRs.md)); superseded/retired records are preserved, never deleted ([`ADR-0012`](../Decisions/ADR-0012-Unverified-Content-Is-Quarantined-Not-Deleted.md) / the legacy snapshot).

## Verification (how compliance is proven)

- [ ] **R1** — a Change Record exists for every boundary crossing; the `Silo(s) crossed` field is filled.
- [ ] **R2** — records are one logical change; unrelated changes aren't combined.
- [ ] **R3** — `git grep` for a corrected old string returns **0**.
- [ ] **R4** — the *doing* doc was fixed, not only the describing one.
- [ ] **R5** — the guide-reconciliation question is answered in writing; no record is `Closed` with an unticked/false box.
- [ ] **Meta** — every change to a rule here traces to an amending ADR + a Change Log row.

## What a violation looks like

A boundary-crossing change with no CR · a correction appended while the error still greps non-zero · the *describing* doc fixed but the *doing* doc untouched · a record marked `Closed` with its Build-Record or reconciliation box unticked.
