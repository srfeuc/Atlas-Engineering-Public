# POL-0006 — Evidence & Verification

> **At a glance.** Every build and change ends with a **read-back**. A tick requires the command *and its output* — not a config line. A clean command is not a correct artefact: check the **wire AND the file**. This policy folds the estate's read-it-back discipline into citable requirements (`POL-0006 R1`…) and doubles as a directory of the decisions that govern verification (below).

## Scope & applicability

Governs how any claim about the estate becomes trusted — at build time, at change time, and in every technical page — across every device, service, and document.

**Boundary with [`POL-0001`](./POL-0001-Atlas-Audit-Policy.md):** POL-0006 is *"prove it when you do it"* — the read-back at the moment of work. POL-0001 is the *standing, scheduled* control that re-checks those claims over time and gates a freeze. They meet at the read-back; POL-0006 requires it, POL-0001 audits that it happened.

## Why this is a policy, not a note

**Five false ticks across three CIS checklists** — each made in good faith from a config line, a memory, or another document — proved Atlas needed this. *"No error was returned"* was the actual root cause of five separate failures in one session: an unbound cert, a SAN-less cert, a config line in the wrong section, a DNS record nothing reads, a setting that didn't persist. Verification that isn't *required* is verification that gets skipped.

## The standing requirements

Each is citable as `POL-0006 R#`.

### R1 — Read the state back

A command completing without error is **not** a confirmed change (Charter Rule 8); prefer live output over recollection. *"No error, so it worked"* is the single most expensive assumption in the estate.

### R2 — A tick needs a command and its output, not a config line

`show run` shows *intent*; `show ntp status` shows *truth* (`POL-0001` R-A1). If you can't paste the output, the box stays unticked.

### R3 — Check the wire AND the file

The runtime and the artefact a rebuild reads are **two different objects** (`POL-0001` R-A2 / `CM-0032`). Four documents verified a cert *on the wire* while the *file* carried a pre-VLAN SAN the whole time; a rebuild from that file fails.

### R4 — The device beats the analysis — including a confident one

Being *listed* is not being reachable; a socket is not a service; a config line is not a working service (Charter Rule 13 corollary). The most confident conclusion — a person's or a bot's — still loses to the read-back.

### R5 — Every technical page declares its reliability

Each carries an **Evidence Status** block — Verified / Historical / Reconstructed / Target Design / Unverified (Charter Rule 14). **`Verified` is a claim about a date**: a page verified in June and untouched is `Historical` today (the `POL-0001` R4d stale-`Verified` sweep enforces it).

## The amendment model — how these decisions relate to this policy

This policy holds the **current** rule; the decisions behind it are the **dated trail**. To change a rule, an ADR carries `Governing Policy: POL-0006`, states *"amends `POL-0006` R#"*, and a Change Log row is added ([`ADR-0054`](../Decisions/ADR-0054-Governance-Reconciliation-Promote-Policy-Shaped-ADRs.md)); preserved, never deleted (legacy snapshot).

## Verification (how compliance is proven)

- [ ] **R1** — build/change records end with a read-back captured from the device, not inferred from an exit code.
- [ ] **R2** — ticked checklist items cite the command output that proves them.
- [ ] **R3** — for any artefact a rebuild reads (certs, configs, ACLs), **both** the wire and the file were checked.
- [ ] **R4** — no inference from a listing is treated as fact.
- [ ] **R5** — every technical page carries an Evidence Status block; none claims `Verified` on 90-day-stale evidence.
- [ ] **Meta** — every change to a rule here traces to an amending ADR + a Change Log row.

## What a violation looks like

A tick made from `show run` / a memory / another doc · *"no error, so it worked"* · the wire verified while the file stayed stale (`CM-0032`) · a `Verified` page last checked months ago · an inference from a listing treated as fact.
