# POL-0008 — Naming & Addressing

> **At a glance.** There is exactly **one** addressing plan and **one** naming convention. Addresses and names are defined once — generated from the source of truth — and **no pre-VLAN or flat-network fossil is ever presented as current**. This policy folds the estate's naming/addressing discipline into citable requirements (`POL-0008 R1`…) and doubles as a directory of the decisions that govern it (below).

## Scope & applicability

Governs every address (IP/VLAN/scope) and every name (device, interface, VLAN, service account) in the estate, and how each is defined, generated, and kept from drifting.

**Boundary with [`POL-0004`](./POL-0004-Source-of-Truth.md):** POL-0004 is the *general* one-home-per-fact / generated-not-typed rule (target NetBox); POL-0008 is its *addressing & naming instance* — the concrete plan and conventions those facts must match. Data-fact ownership is POL-0004; the addressing plan is POL-0008's own artefact.

## Why this is a policy, not a note

Atlas has a documented addressing **drift** — `10.0.0.x` vs `10.10.0.x` appearing in different docs — and SNMP pointed at `10.40.0.52`, a host that does not exist, and RADIUS pointed at a pre-VLAN address. Each is a **fossil**: an old value that outlived its truth and was presented as current. One plan, generated, is the structural fix.

---

## The standing requirements

Each is citable as `POL-0008 R#`.

### R1 — One authoritative addressing plan

Every address traces to [`IP-Addressing-Plan-VLSM`](../../Labs/Lab-02-Cisco-Core/Architecture/IP-Addressing-Plan-VLSM.md) (this policy's own artefact): VLSM, VLAN-encoded, gateways on MKT01, transit `/30`s in `10.255.x`. No second addressing table.

### R2 — Generated, not typed

Addresses render **from NetBox** (overlaps [`POL-0004`](./POL-0004-Source-of-Truth.md)); `006`-style tables become **exports**, never hand-maintained competitors that drift.

### R3 — Consistent naming everywhere

Device (`SW01`, `DC01`), interface, VLAN (10 Mgmt … 90 OT), and service-account (`svc-gmsa-<purpose>`) conventions per `007`/`008`. **A name means the same thing everywhere.**

### R4 — No fossils

A pre-VLAN/flat address or a decommissioned host must **never** appear in a *current* doc as if live. The device is the truth (Charter Rule 13); reconcile the doc to it.

### R5 — An addressing change is a change to the plan

Change the **plan** (and NetBox), not just the device — or the plan drifts and the next generated ACL/binding is wrong. (A device-only edit is the drift `R2` exists to prevent.)

## The amendment model — how these decisions relate to this policy

This policy holds the **current** rule; the decisions behind it are the **dated trail**. To change a rule, an ADR carries `Governing Policy: POL-0008`, states *"amends `POL-0008` R#"*, and a Change Log row is added ([`ADR-0054`](../Decisions/ADR-0054-Governance-Reconciliation-Promote-Policy-Shaped-ADRs.md)); preserved, never deleted (legacy snapshot).

## Verification (how compliance is proven)

- [ ] **R1** — exactly one addressing plan exists; every doc's addresses match it.
- [ ] **R2** — no address is authoritatively defined in two places; tables are exports, not hand-typed competitors.
- [ ] **R3** — device/interface/VLAN/service-account names follow `007`/`008` consistently.
- [ ] **R4** — no fossil (a `10.40.0.52`-style nonexistent target, a pre-VLAN address) appears in a current doc; device addresses match the plan on the wire.
- [ ] **R5** — addressing changes touch the plan + NetBox, not just the device.
- [ ] **Meta** — every change to a rule here traces to an amending ADR + a Change Log row.

## What a violation looks like

A second addressing table · a device addressed off-plan · SNMP/RADIUS/DNS pointed at an address the plan doesn't contain · a pre-VLAN fossil presented as current · hand-typed addresses drifting from the source of truth (the `006` defect).
